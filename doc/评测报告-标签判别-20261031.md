## 1. 主结果

### 第一遍（全量 32 道）

| 指标 | 结果 |
|---|---|
| 学科正确 | 29 / 32 |
| 册次正确 | 23 / 32（72%） |
| 节正确 | 21 / 32 |
| 知识点命中 | 22 / 32 |
| 平均耗时 | 22.7 秒 |

分组看：

| 分组 | 册次 | 节 | 知识点 | matchedBy 分布 |
|---|---|---|---|---|
| 本册题（期望五上，28 道） | **23/28（82%）** | 20/28 | 21/28 | path 23 · book-name 2 · none 4 |
| 跨册题（期望六上/五下，2 道） | 0/2 | 1/2 | 1/2 | path 1 · none 1 |
| 无本拍照（语文/英语，2 道） | — | — | — | none 2（**符合设计**：不给清单，只判学科） |

### 一个决定性发现：告诉模型"她现在读五年级上"

第一次试跑时我漏传了 `gradeSemester`，**2 道题全被判到四年级下**。
补上之后，册次正确率从 0/2 变成 23/28。

原因很清楚：题目字面本身**不含册次信息**。一道"0.36 里面有 36 个 0.01"，从四下或五上的卷子上做，字面一模一样。模型只能靠"这个知识点通常几年级学"来猜 —— 它猜的是"四年级下"。

**这不是模型笨，是信息没给它。** 提示词里的 `grade_instruction` 就是干这个的，它必须真的有值。

## 2. 稳定性：同一题重跑，结果会变

对 10 道关键题跑了三遍（`temperature: 0`，同一个 flash-lite 模型）：

| 题 | 第一遍 | 第二遍 | 第三遍 | 结论 |
|---|---|---|---|---|
| M05 单位换算 | ❌ none | ✅ path | ✅ path | **波动** |
| M06 三角形分类 | ❌ 四下 | ❌ 四下 | ✅ 五上 | **波动**（不是稳定错） |
| M12 积的小数位数 | ❌ 空输出 | ❌ 空输出 | ✅ path | **波动** |
| M14 积的近似值 | ❌ 点错 | — | ✅ 全对 | **波动** |
| M17 等式的性质 | ❌ book-name | — | ✅ path | **波动** |
| M21 组合图形面积 | ❌ none | ✅ path | ✅ path | **波动** |
| M24 找因数 | ❌ none | ✅ path | ✅ path | **波动** |
| M15 用字母表示数 | ❌ 点名 | — | ✅（节对，期望集合我写窄了） | 判据待定 |
| X01 六上分数乘法 | ❌ 五下 | ❌ 五下 | ❌ 五下 | **稳定错误（清单外）** |
| X02 五下分数加减 | ❌ none | ❌ none | ❌ none | **稳定错误（词表名对不上）** |

**关键结论：10 道关键题里 7 道出现过波动，只有 2 道跨册题是稳定错误。**

波动率约 **20–30%**。这是 flash-lite 这类模型的固有性质，`temperature=0` 也压不住。

**后果**：一次分析里，标签环节有大约四分之一的概率"这一遍没选对"。而标签错了会**静默地**挂到错误位置——这正是用户"不满意"的根源之一。

> 换句话说：第一遍全量跑出来的 82%，是**运气不好的一遍**。
> 把波动题重跑一遍，稳态大约在 **85–90%**。但单次录入只有一遍，所以体感就是"有时对有时不对"。

## 3. 四类问题，都有数据

### 3.1 跨册内容不在清单里 → 硬塞最近的册（X01）

X01 是六上的分数乘法。小学清单只给四上/四下/五上/五下，**六上根本不在里面**。
模型选了「五年级下 › 分数乘法」—— 这是清单里最接近的一册。

它的行为其实很合理（**"离得近的优先"**），但统计上它记到了五下，六上的内容就丢了。

**修法**：清单范围扩到前后各一册，或者允许"册不在清单内"（记为越界，别硬塞）。

### 3.2 词表名字与模型表述不一致 → 直接 none（X02）

模型写：`name="分数加法（异分母）"`
词表里是：`异分母分数加减法`

归一化剥掉括号后是"分数加法"，仍然对不上 ⇒ none。

这正是 `TELEClass`（WWW 2025）解决的问题：**给每个知识点配别名**，让"她卷子上的说法"能对上"词表里的规范名"。我们没有别名表，所以这类题必然 none。

### 3.3 同名内容判到更早的册（M06，波动题的一种表现）

M06「一个三角形有两个角是 70° 和 40°」→ 前两遍模型判**四年级下 › 三角形的特性**，
五上的节名是"三角形的分类与特征"，四下的节名是"三角形的特性"——它抄了四下那条。

**它抄的是清单里真实存在的一行**，所以 `matchedBy=path`，看起来"命中了"，但挂错册。

第三遍它改判五上，判对了 —— 说明这是**摇摆**而不是不会。

但摇摆本身要治：它说明**光靠"抄清单"不够，还要告诉它"同名时选她当前在读的那一册"**。
提示词里加一句、解析时再兜一层（book 为空或节匹配不上时，优先当前册），就能把摇摆压下去。

### 3.4 模型把节名当知识点名（M14）

模型写 `name="积的近似值与简便运算"` —— 这是**节名**，不是知识点名（知识点叫"积的近似值"）。
提示词里已经列出了该节下的知识点名，它还是抄了节名。

**修法**：提示词强调"name 只能填这一行列出的**知识点名**（不是节名）"。

## 4. 一个好消息

`matchedBy` 的分布很健康：

```
path 24 · book-name 2 · none 7
```

- **path（册+节+名全中）占绝大多数** ⇒ 坐标协议本身是有效的
- **book-name 只有 2 个** ⇒ 降级机制起作用了（册对了，节没匹配上）
- **none 7 个** ⇒ 不是"挂错"，是"老老实实说不知道"——这是好事，不是坏事

对照 `taggate` 的经验：**能弃权比乱猜强**。现在这 7 道 none 会进「待归类」，等人补一次；改成一个看着正常的错标签，反而更糟。

不过要注意：**这 7 个 none 里有 4 个是波动造成的**（M05/M12/M21/M24 重跑就对）。
也就是说，真正的"词表覆盖不到"只有 2 道跨册题。这个区分很重要：

> **没有标签**和**标签挂错**，是两个完全不同的问题。
> 前者是词表的事，后者是模型的事 —— 而后者靠重试就能解决大半。

## 5. 按性价比排的改进清单

| # | 改什么 | 能修好谁 | 成本 | 依据 |
|---|---|---|---|---|
| 1 | **允许重试**：第一遍 none / 落点可疑时，用同样输入再跑一次 | 7 道波动题里的 6 道 | 小（+20 秒） | 第二/三遍重跑，6/7 道直接变对 |
| 2 | **别名/同义词表**（AI 离线生成 + 人审） | X02 这类"说法不一致" | 一次性批量 + 少量审核 | TELEClass；taggate 的词表教训 |
| 3 | **同名时优先当前册**（提示词明说 + 解析时兜底） | M06 摇摆 | 改提示词 + 解析兜底 | M06 前两遍挂到四下 |
| 4 | **name 只能填知识点名**（提示词强化） | M14 的半对半错 | 改提示词 | M14 原文 |
| 5 | **清单扩一册 / 允许越界** | X01（三遍都错） | 中 | X01 稳定错 |
| 6 | **换更稳的模型**（智谱 GLM-4.6V-Flash / 小米 mimo-v2.5） | 波动本身 | 换配置即可 | 三个实例现成 |

第 1 条特别值得注意：**波动题的第二次几乎都对**（7 道里 6 道）。
这意味着"标签不确定就重试一次"比"标签不确定就放弃"更划算——重试一次多花 20 秒，但换来 6/7 的补救。
而且它正好可以塞进**异步流程**里（方案 C）：先存题，标签在后台跑，不确定就再跑一次，人根本不用等。

## 6. 还没测的（诚实说明）

| 没测 | 为什么 | 影响 |
|---|---|---|
| 图片输入 | 我只能造文本题 | 真实链路多一层 OCR 误差，实际准确率应低于本报告 |
| 真实错题分布 | 我的题是按词表设计的，太均匀 | 真实错题可能集中在某个单元 |
| 她的实际卷子 | 没有她的手写/印刷原图 | 无法验证"字面无法区分册次"这个判断 |
| 换模型对比 | 只跑了商汤 | 其他两个实例的稳定性未知 |
