## 三处"以前必错、现在能对"

### 1. 英语：召回从 0 变成 32

原来关键词是"阅读理解"，而小学英语词表叫"短文阅读" —— **词对不上，检索召回 0**，
第二段连选项都没有。

现在这五科（语英政史地）**不看关键词、整学段全送**。小学英语整学段也就 32 个节，
筛一遍只会把正确答案筛掉 —— 这正是用户当时的判断：

> 第一段本来就在猜，第二段才有选项确认。猜不准就把选项砍掉，等于让第一段的错误惩罚第二段。

### 2. 大雁塔：跨册题落到了四下

这是两段式最直接的收益：

```
单段式：五上 › 用字母表示数量关系      ← 它在这册里，字面对得上，但不是这题
两段式：四下 › 列方程解决问题          ← 对
```

关键词命中四下「认识方程」那一节 → 同章其他节一起进候选 → 第二段从里面挑。

### 3. 标签落到**知识点**，不是节

之前第二段只选到"节"，落库落的是节节点，比单段式粗一级，
而且"节"和"同名知识点"都存在时取哪个取决于数据库顺序。

现在第二段多输出一个 `<kps>`（要求逐字照抄候选里那行），落库时在节节点的子节点里匹配。
实测两道题给的点都是真的，没有编造。

## 工程量：这一轮改了什么

| 改动 | 为什么 |
|---|---|
| **第二段改串行队列** | 批量保存 20 道会同时发 20 个请求 → 全部撞限流。用户明确要求"一个一个来" |
| **请求加超时** | 原来 `fetch` 没有超时。串行队列下一道卡死 = 全线停摆，且不报错 |
| **落库到知识点** | 见上 |
| **同章扩展** | 关键词说"列方程"、实际考"解方程" —— 只带命中的那一节，同章正确项进不了候选 |
| **去掉了「猜年级」** | 用户否定过；模型也判不准（大雁塔判成"五年级下"）。年级改由"落在哪一册"自己算 |
| **册名归一** | 线上库有 7 种写法（`五年级/上学期`、`Grade 6, 1st Semester`…），词表只认一种；认不出 = 当前册候选全丢 |
| **人已介入就作废** | 用户手选了标签，第二段跑完会覆盖 —— 人比机器可靠 |

## 耗时

| | 单段式（历史） | 两段式（本次） |
|---|---|---|
| 正常 | 70–110 秒 | **30–102 秒** |
