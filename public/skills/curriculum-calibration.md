# Skill：用新书校准知识点词表

> 适用对象：接手的 AI（或人）。
> 触发时机：**升年级、换学期、换教材版本**，或者发现"某道题怎么都挂不上标签"。
> 这份说明书的目标只有一个：**让词表和她的书逐条对上**。

---

## 0. 先记住三条铁律

1. **词表的第一优先级不是"全"，是"跟她的教材一致"。**
   错一册，那一册的题全废。宁可少覆盖，不能张冠李戴。
2. **不要凭印象改。** 教材版本不同，同一个内容可能差两册
   （实例：北师大版旧版"小数除法"在四下第七单元，新版挪走了；我们照旧版抄，正好错一册）。
3. **改之前先备份、改之后必须验。** 词表是全局的，改错影响所有题。

---

## 1. 确认教材版本（最容易错的一步）

**不要猜。** 让他拍两张照片：

- 那一册的**目录页**（有单元编号和页码）
- 版权页（出版社 + 版次，如"北京师范大学出版社，2014年12月第1版，2020年修订"）

**只认目录页上的单元名。** 网上搜到的"XX版目录"经常混着新旧版、不同出版社，
搜到的东西只能用来**补充课时结构**，不能用来定单元名。

---

## 2. 词表在哪里

```
src/lib/tag-data/
  math.ts       数学（按册：一年级上 … 六年级下，七年级上 … 高三）
  chinese.ts    语文（按学段：小学 / 初中 / 高中）
  english.ts    英语（按学段）
  physics.ts / chemistry.ts / biology.ts   按册
  history.ts / geography.ts / politics.ts  按学段（历史多一层"时期/阶段"）
```

结构是四层，**深度不同学科不一样**：

```ts
'五年级上': [                        // 第 1 层：册（语文/英语是"学段"）
  {
    chapter: '第一单元 小数的再认识和加减法',   // 第 2 层：章
    sections: [
      {                                   // 第 3 层：节
        section: '单位换算与复名数',
        tags: ['长度单位换算', '质量单位换算', '单名数与复名数互化'],  // 第 4 层：知识点
      },
    ],
  },
]
```

> 地理/政治只有两层（`chapter` + `tags`，没有 `sections`），重建脚本两种都支持。

---

## 3. 逐条对照（这一步决定了准不准）

把目录页上的**每一个单元**，和词表里的 `chapter` 一一对上，做一张表：

| 目录页上的单元名 | 词表里的 chapter | 结论 |
|---|---|---|
| 第一单元 小数的再认识和加减法 | 同左 | ✓ |
| 五 认识方程 | 第五单元 小数除法 | ✗ **改** |

判断标准（按顺序）：

1. **单元名逐字比对**——差一个字也要改（"图形的位置与运动" vs "图形的平移与运动"）。
2. **数量对不对**——目录有几个单元，词表就该有几个（"整理与复习""数学好玩"这类
   可以不合，但要知道自己跳过了哪些）。
3. **顺序对不对**——第几单元要对得上，不是"内容都在就行"。
4. **课时/小节**——目录只给单元时，用教材配套的课时目录补 `sections`；
   补不到就按"这一单元的知识块"自己切，不要硬凑。

---

## 4. 改词的三个坑（都踩过）

### 坑 1：叶子名一改，已有题的关联就断
重建脚本是按**名字**恢复关联的。改名 = 那批题变回"没归类"。
> 如果库里还是测试题，随便改；**进入生产后**，改名要同时给出迁移映射。

### 坑 2：同名节点在多个册/多个学科下都存在
「小数减法」五上有、五下也有；「计算」数学有、物理也有。
- 重建脚本靠 `parentId` 区分，不会混；
- 但**代码里按名字查**的地方会混（这就是为什么按标签筛题必须用 **id**，不能用名字）。

### 坑 3：学段不同，分册方式不同
- 小学/初中：一年级上 … 九年级下（一年两册）
- **高中：高一上/下、高二上/下、高三（高三不分上下）**
- 语文/英语/历史/地理/政治：**没有"册"，只有学段**

写错这一层，`bookKeyOf` 会把它归一成别的册，然后整册的题都挂不上。

## 5. 改完之后必须验的四关

```bash
# ① 类型
npx tsc --noEmit --incremental false -p tsconfig.json

# ② 词表相关单测（含"全库每条 path 命中"）
./node_modules/.bin/vitest run \
  src/__tests__/unit/tag-resolve.test.ts \
  src/__tests__/unit/tag-resolve-regression.test.ts \
  src/__tests__/unit/tag-path.test.ts \
  src/__tests__/unit/tag-tree.test.ts \
  src/__tests__/unit/ai/tag-scope.test.ts \
  --pool=threads --testTimeout=90000

# ③ lint 门禁（只拦新增）
npm run lint:gate

# ④ 真实题评测（要 NAS 上的库和配置）
DATABASE_URL="file:<仓库>/prisma/dev.db" TAG_EVAL=1 \
  TAG_EVAL_ONLY=<题号,题号> \
  ./node_modules/.bin/vitest run src/__tests__/eval/two-stage-eval.test.ts \
  --pool=threads --testTimeout=2400000
```

**评测怎么跑**：
1. 从 NAS 取 `dev.db` → `prisma/dev.db`，`app-config.json` → 仓库外（**别提交**）
2. 在 `src/__tests__/eval/real-cases.ts` 里加用例（**每条都要写"这道题暴露了什么问题"**）
3. 跑，看 `召回 x/n · 命中 x/n`
4. 跑完删掉 `prisma/dev.db` 和配置文件（里面有 apiKey）

## 6. 词表怎么进到线上

改完 `src/lib/tag-data/*.ts` → push → 发版（构建镜像）→ 容器启动时
`scripts/rebuild-system-tags.ts` **按词表内容指纹**自动重建（不再看版本号），
并保留已有的题目关联。

> ⚠️ **`prisma/.tags_hash` 那个指纹文件不要提交进仓库** —— 提交了会让容器以为
> "词表已同步"而跳过重建。已在 `.gitignore` 里。

---

## 7. 判断"改对了没有"的两个实证

**① 那道一直挂不上的题，现在能挂上了。**
实例：大雁塔那道一元一次方程，改对了四下第五单元「认识方程」之后，
两段式能落到「四年级下 › 第五单元 认识方程 › 列方程解决问题」。

**② 同一章下的不同题，路径不再一样。**
反例：词表把"节"写错了，三道题的标签都显示成同一个章 —— 那是显示问题，不是词表问题，
但两者都会表现为"怎么都一样"，要分清。

## 8. 一次标准作业的清单（照着打勾）

- [ ] 拿到**目录页**照片（不是搜索来的）
- [ ] 确认出版社 + 版次
- [ ] 逐单元对照，列差异表给他**确认**
- [ ] 只改差异项，**不动对的部分**
- [ ] 改了叶子名 ⇒ 说明"已有题会失去关联"
- [ ] tsc / 单测 / lint / 真实题评测 四关
- [ ] 写清楚"改了什么、为什么、影响哪一册"
- [ ] push 后看 CI（构建期错误，本地四关全绿也拦不住）
